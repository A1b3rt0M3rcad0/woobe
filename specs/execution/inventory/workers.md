# Current worker inventory

- Worker contracts and registry protocols live in `src/shared/workers/`.
- `src/shared/workers/runner.py` coordinates lifecycle for dedicated worker processes.
- `src/shared/workers/discovery.py` resolves module worker registries.
- RabbitMQ connection management is implemented in shared worker infrastructure.
- Agent workers publish outbox events and consume supported external integration events.
- Agent async ask jobs execute outside the API request process.
- Identity workers publish identity outbox events.
- Core workers publish and consume project-domain integration events.
- Observability workers consume execution events and persist trace projections.
- Metering workers consume usage events and maintain metering projections.
- Billing workers consume billable usage and maintain billing projections.
- Each Consumer persists InboxEvent state before acknowledgement.
- Each Dispatcher claims pending OutboxEvent rows with bounded concurrency.
- Retryable failures update attempts and available-at timestamps.
- Terminal failures move to dead-letter state with redacted error information.
- Dedicated entrypoints under `src/workers/` are used by Compose worker services.
- API startup does not duplicate worker consumers inside the web process.
- Container health and shutdown paths close RabbitMQ and HTTP resources.
- Worker integration tests verify registry, inbox, outbox and lifecycle contracts.
